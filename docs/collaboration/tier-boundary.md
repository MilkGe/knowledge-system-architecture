# 操作权限分级 (Tier Boundary)

定义 AI 在知识系统中的三级操作权限。AI 在执行任何操作前，先判断属于哪个 Tier。

## 三级权限

```
Tier 3（AI 自动执行）        Tier 2（AI 执行 + 通知）       Tier 1（必须人工确认）
┌─────────────────────┐     ┌─────────────────────┐     ┌─────────────────────┐
│ 读取文件             │     │ 写入 YAML            │     │ 创建新笔记           │
│ 搜索仓库             │     │ 建议标签和链接       │     │ 删除/移动笔记        │
│ 格式化修复           │     │ 更新索引文件         │     │ 改变 PARA 归属       │
│ 更新 updated 字段    │     │ Inbox 分类建议       │     │ 修改系统配置文件      │
│ 生成报告             │     │ 批量元数据补全       │     │ 合并笔记内容          │
│ 提取关键词           │     │ 归档已完成项目       │     │ 批量移动文件          │
└─────────────────────┘     └─────────────────────┘     └─────────────────────┘
```

### Tier 3：自动执行

**特征**：只读或非破坏性操作，出错不影响笔记内容。

| 操作 | 说明 |
|------|------|
| 读取文件 | 读取任何 .md、配置文件的完整内容 |
| 搜索仓库 | 搜索文件名或内容 |
| 格式化修复 | 修复不规范的 markdown 语法 |
| 更新 `updated` 字段 | 在 frontmatter 中更新修改时间 |
| 生成报告 | 生成系统健康报告、Inbox 状态报告等 |
| 提取关键词/摘要 | 从正文中提取关键信息用于索引 |

**判断标准**：操作后笔记内容不变，或仅改动了时间戳等非内容字段。

### Tier 2：执行 + 通知

**特征**：修改笔记元数据或结构，但可回滚。AI 执行后通知用户做了什么，用户发现不对可以撤销。

| 操作 | 说明 |
|------|------|
| 写入/修改 YAML frontmatter | 补充 type、status、tags、priority 等字段 |
| 建议并添加标签 | 提取关键词后为笔记添加 tags |
| 更新索引文件 | 更新索引文件的内容列表 |
| Inbox 分类建议 | 建议每篇 Inbox 笔记的 PARA 归属 |
| 批量元数据补全 | 为多篇笔记批量补全 frontmatter |
| 归档操作 | 将已完成项目移入 Archive |

**判断标准**：修改的是元数据而非正文核心内容，用户可手动回滚。

### Tier 1：必须确认

**特征**：不可逆或影响系统结构的操作。AI 必须列出具体方案，等用户明确确认才能动手。

| 操作 | 说明 |
|------|------|
| 创建新笔记 | 在 PARA 任意目录下创建新的 .md 文件 |
| 删除笔记 | 将笔记移入回收站（不永久删除） |
| 改变 PARA 归属 | 将笔记从一个目录移到另一个目录 |
| 修改系统配置文件 | 修改入口文件、策略定义文件等 |
| 合并笔记 | 将两篇笔记的内容合并为一篇 |
| 批量移动文件 | 一次性移动多个文件到不同目录 |

## 使用方式

AI 执行操作前：

1. 我要执行的操作是什么？
2. 查 tier-boundary → 属于哪个 Tier？
3. Tier 3 → 直接执行，执行后记录
4. Tier 2 → 执行，执行后通知用户
5. Tier 1 → 列出方案，等用户确认再执行

## 边界注意事项

- 边界不是绝对的——如果某个 Tier 2 操作涉及特别敏感的内容，AI 应主动升级到 Tier 1
- 用户始终可以覆盖 Tier 级别："这个你直接做就行"（降级）或"这个先问过我"（升级）
- 新操作类型出现时，先按 Tier 1 处理，等明确边界后再归类
