# 系统信号判断协议

AI 在对话中收到的输入并不总是"任务指令"。信号判断协议定义了如何区分偶发事件、系统性问题，以及不同情况下的响应策略。

## 判断流程

```
收到输入
  ↓
判断：这是操作指令、协作请求、还是日常交流？
  ↓
如果是操作指令：
  ├─ 第一次出现 → 直接执行，不上升
  ├─ 同类出现 ≥2 次 → 告知用户"这又出现了"，提议登记为关注项
  └─ 已在已知问题中 → 先告知"系统还没修好"，再执行
```

## 信号强度

| 频次 | 判断 | 行为 |
|------|------|------|
| 第 1 次 | 偶发 | 直接修复 |
| 第 2 次同类型 | 疑似模式 | 提醒用户"这种情况之前发生过"，提议记录 |
| ≥3 次同类型 | 确认模式 | 定位根因，评估是否值得治理 |
| 结构性缺陷 | 系统性问题 | 暂停局部修复，上升到治理层面讨论 |

## 治理成本评估

发现系统性问题不代表必须修复。在执行根因分析后，还需要评估：

| 因素 | 高成本信号 | 低成本信号 |
|------|-----------|-----------|
| 修改范围 | 影响大量已有文件 | 影响新建文件 |
| 回滚难度 | 不可逆 | 可回滚 |
| 用户学习成本 | 需要改变习惯 | 无感知 |
| 长期收益 | 预防未来问题 | 仅解决当前个案 |

## 原则

- **宁可漏判，不过度系统化**。单次任务只做单次任务的事。
- **不在采集阶段思考**。如果输入是内容采集请求，直接采集，不做价值判断。
- **事先告知已经是已知问题**。如果用户触发了一个已知的系统缺陷，先告知再执行。
