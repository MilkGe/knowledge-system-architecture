# 设计决策记录

这个系统的架构并非一次性设计完成——它经过了一轮从复杂到精简的演化。以下是关键决策的动因和取舍。

## 决策 1：五层 → 三层

### 背景

最初的架构分为五层：采集 / 结构 / 标注 / 流转 / 治理。

### 问题

五层架构在纸面上逻辑清晰，但在实际运行中暴露了问题：

- **标注层与结构层的边界模糊**。YAML、标签、wikilink 本质上是文件结构的一部分——给文件添加元数据和链接是结构行为，不值得独立成层。
- **流转层过于形式化**。设计了 4A/4B 双层状态机、概念对象模型、关系语义、合成协议、抽象压缩等一系列机制。但认知的演化不需要这么复杂的协议——人处理知识的方式是不规则的。
- **治理层不是架构层**。权限、命名规范、协作协议是系统策略配置，它们决定了系统怎么运行，但不改变系统由什么构成。把策略放在架构层里产生了"治理是架构的一部分"的错觉，导致每次调整策略都需要修改架构定义。

### 决策

精简为三层：采集 / 结构 / 演化。标注层并入结构层。流转层降级为演化层中一组简单的状态标记+动作模型。治理层移出架构，作为独立的策略配置。

### 取舍

- **优势**：每层对应一个根本问题，不多不少。新 contributors 理解成本大幅降低。
- **代价**：失去了对知识流转过程的精细追踪——但通过"养料消耗模型"和沉淀信号弥补。
- **判断**：可运行的最小闭环比完备的理论分层更有价值。

## 决策 2：消除独立的概念对象体系

### 背景

早期设计中，系统维护了一个独立的概念对象层——概念被建模为有独立 ID、属性、关系的实体，笔记文件只是这些概念对象的"视图"。

### 问题

- 概念对象的维护成本高于其收益——每次新增笔记都需要决定它关联到哪个概念对象
- AI 生成的概念对象往往只是对文件内容的重新描述，没有增加信息量
- 概念存在于文件中——通过 wikilink、标签、正文中的定义来表达，不需要独立的抽象实体

### 决策

取消独立的概念对象体系。文件就是知识对象。概念通过文件间的关系来隐式表达。

### 取舍

- **优势**：消除了一整套维护负担。系统的原子单元从"概念"降级为"文件"，操作更直观。
- **代价**：失去了跨文件的语义查询能力——但通过 YAML 元数据 + Dataview 查询可以弥补大部分需求。

## 决策 3：养料消耗模型

### 背景

Inbox 是系统的入口点，但随着采集管线自动化程度提高，Inbox 积压变成了常态。如果不定义 Inbox 中内容的生命周期，系统会膨胀为"所有东西都在 Inbox 里永不处理"。

### 问题

把 Inbox 内容当作永久存储来处理和维护是不合理的——它们是消耗品，不是资产。

### 决策

定义"基础养料消耗模型"：

- 外源内容（视频转录、文章摘录、链接）是消耗品。加工后原始文件不保留。
- 个人思考笔记本身就是半成品，加工后保留。
- 多篇同主题内容可以合并为一篇，原始文件全部删除。
- 加工后的笔记要去掉来源痕迹，读起来像自己写的，不是来源索引。

### 取舍

- **优势**：防止 Inbox 无限膨胀。笔记质量提升——合并后的笔记比单篇更有价值。
- **代价**：失去了对原始来源的完整回溯能力——但 source_url 在 raw 阶段保留，加工后可选择性留存。

## 决策 4：结构层最小集原则

### 背景

结构层最初包含了大量可选字段和复杂分类。

### 问题

每一个额外字段都是维护负担。如果做了分类但从不使用，这个分类就是噪音。

### 决策

YAML 元数据限定在最小必填字段（type / status / created / updated）加上个别情境字段。不再增加其他字段。标签平级、不建层级。wikilink 不需要语义分类。

### 取舍

- **优势**：创建笔记的心理负担极低。系统不强迫用户在记录时思考分类问题。
- **代价**：对于需要精细组织的人，这个结构可能太"薄"了——但这一类用户可以自然地扩展，而不会破坏系统的基础。

## 决策 5：采集层不思考

### 背景

在早期运行中，AI 常在采集阶段就开始对内容进行分类、判断价值、建立关联——这些行为跨越了采集层和结构层的边界。

### 问题

采集阶段做深度加工会导致两个问题：
1. 用户在 Inbox 中看到的内容已经被"加工过"，失去了原始形态
2. AI 的分类判断可能不准确，给后续处理造成干扰

### 决策

明确规定：采集层只负责"拿到"和"初步格式化"，不做任何深度加工。分类、关联、价值判断都发生在结构层和演化层。

### 取舍

- **优势**：职责边界清晰。Inbox 中的内容保持原始形态，人可以看到完整的未经处理的信息。
- **代价**：Inbox 可能包含"看起来还没处理完"的内容——但这是设计目标，不是缺陷。
