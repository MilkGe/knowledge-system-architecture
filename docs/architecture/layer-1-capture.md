# 采集层 (Layer 1: Capture)

信息从外部世界进入知识系统的全部通道和预处理。

## 设计原则

**采集层不思考。** 分类、判断、关联都发生在结构层和演化层，不在采集层。采集层只负责"拿到"和"初步格式化"，不做深度加工。

如果一个采集模块开始涉及"理解内容并做判断"，说明它越界了——需要拆分为两个模块分属采集层和其他层。

## 当前支持的采集通道

### 1. URL 自动采集

支持平台：抖音、B站、小红书、微信公众号。

工作流程：

```
收到 URL
  ↓
识别平台（域名匹配）
  ↓
调用对应采集策略
  ↓
输出结构化 JSON（含元数据 + 转录文本）
  ↓
结构化整理 → 写入 Inbox
```

**各平台处理策略**：

| 平台 | 采集方式 | 转录 | 输出 |
|------|---------|------|------|
| 抖音 | MediaCrawler 或独立采集 | 音频下载 → ASR | JSON |
| B站 | yt-dlp 下载音视频 | 音频提取 → ASR | JSON |
| 小红书（视频帖） | 采集元数据 + 下载音视频 | 音频提取 → ASR | JSON |
| 小红书（图文帖） | 下载图片直链 | 无（视觉分析） | JSON |
| 微信公众号 | web_fetch 提取文章内容 | 无 | JSON |

### 2. 手动创建

通过 Obsidian CLI 或其他编辑器手动写入 Inbox。遵循统一的 YAML 元数据和命名规范。

### 3. 其他通道

浏览器剪藏、API 推入等可根据需求扩展——新通道只需实现"输入 → 格式化 → Inbox"的接口。

## 结构化输出规范

采集层产出的每篇笔记必须遵循以下规范。

### 文件名

```
<内容概要>.md
```

- 用标题的核心关键词命名，不含日期前缀
- 中文 + 英文连字符，不超过 40 字符
- 例：`AI编程分水岭-管Agent不是写代码.md`

### YAML 元数据

**属性名用英文，属性值用中文自然语言**。

| 属性 | 值规则 | 示例 |
|------|--------|------|
| `type` | `inbox` | `type: inbox` |
| `source_url` | 原文链接 | `source_url: "https://..."` |
| `source_platform` | 中文平台名 | `"抖音"` / `"小红书"` / `"B站"` |
| `source_author` | 作者/账号 | `"硅谷赵博"` |
| `collected_at` | ISO 8601 含时区 | `2026-05-12T20:43:00+08:00` |
| `collected_by` | 采集者 | `"jarvis"`（或用户名） |
| `content_type` | 内容形态 | `"视频"` / `"图文"` / `"文章"` |
| `transcribed` | 布尔值 | `true` / `false` |
| `transcript_model` | 转录引擎 | `"SenseVoice-Small"`（仅转录时） |

**`collected_at` 格式**：必须使用 ISO 8601 的 T 分隔格式，否则 Obsidian 无法识别为日期类型字段。

### 转录文本排版

ASR（自动语音识别）输出写入笔记前需经过二次排版：

1. **段落划分**：按语义自然分段，3-5 句一段
2. **标点规范**：统一中文标点，补全句末句号
3. **口语修正**：修正明显 ASR 错字，不改变原意
4. **说话人标识**：多说话人时用 `**A：**` / `**B：**` 标记
5. **结构**：转录内容放在二级标题下，结构化要点保持原样不动

## 注意事项

- 采集阶段不加标签。标签在结构层分类时引入
- 不在文件名中加日期——日期只存在 YAML 的 `collected_at` 字段
- 采集来源的元数据（source_url 等）在 raw 阶段有价值，笔记状态推进后可删除——让笔记读起来像自己写的

## 典型处理流程

以 URL 自动采集为例，完整步骤：

```
收到 URL → 平台识别 → 元数据提取 → 
  ├─ 视频类：下载音频 → ASR 转录 → 结构化作笔记
  ├─ 图文类：下载图片 → 视觉分析 → 结构化作笔记
  └─ 文章类：提取文本 → 格式化 → 结构化作笔记
  ↓
写入 Inbox → 在 Inbox 中等待结构层处理
```
