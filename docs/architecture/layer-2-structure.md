# 结构层 (Layer 2: Structure)

知识单元如何稳定存在——目录体系 + 元数据 + 命名规则 + 链接约定。

## 核心模块

### 目录体系：PARA

基于 Tiago Forte 的 PARA 方法，四分类管理所有笔记：

| 目录 | 存放内容 | 生命周期 |
|------|---------|---------|
| **01-Projects** | 有具体目标和截止日期的工作项 | 创建 → 完成 → 知识提取 → 归档 |
| **02-Areas** | 需要长期维护的知识领域 | 持续积累，不归档 |
| **03-Resources** | 可反复查阅的参考资料、文献笔记 | 按主题组织，不归档 |
| **04-Archive** | 已完成/过期的项目或知识 | 归档后保留结构化摘要 |
| **00-Inbox** | 采集层产出，等待处理 | 暂存，处理后移出 |

辅助目录：

| 目录 | 用途 |
|------|------|
| **05-Templates** | 笔记模板 |
| **06-Attachments** | 图片、PDF 等附件 |
| **07-Daily** | 日记、日常记录 |

### 内容模型

每种笔记类型有固定的内容结构：

**Project 笔记**：轻量进度板。包含 Overview + Goal + Tasks + Log + 链接。深度知识内容不写在 Project 里，通过 wikilink 指向 Resources 或 Areas。

**Area 笔记**：系统化的知识领域。写原理、标准、方法论、最佳实践。不跟具体文献绑定。

**Resource 笔记**：文献笔记、调研报告、原始数据。侧重于参考资料的价值。

### YAML 元数据

**最小必填字段**：

```yaml
type: [inbox | project-note | area-note | resource | daily]
status: [raw | seed | developed | stable | archived]
created: YYYY-MM-DD
updated: YYYY-MM-DD
```

**可选情境字段**：

```yaml
source: "来源 URL"
tags: [标签1, 标签2]
project: 所属项目名
area: 所属领域名
stage: [按需使用]
```

不再增加其他字段。YAML 应保持最小集，避免过度结构化。

**关于 source 类字段**：采集管线产出的 source_url / source_platform / source_author 等字段在 raw 阶段有溯源价值，但在笔记状态达到 seed 或 developed 后可以删除。目标是让笔记读起来像自己写的，而非"一篇来自某处的笔记"。

### 标签规范

- 平级结构，不建层级
- 每篇 1-3 个标签为宜
- 避免将 status 信息重复写进标签（已有 status 字段）
- 标签是检索工具，不是分类树

### wikilink 约定

`[[A]]` → `[[B]]` 是**上下文引用**，不是知识图谱。

- 绝大多数 wikilink 只表达"这篇内容与那篇有关"，不需要语义分类
- 不需要关系类型、方向、权重
- 单向链接有价值——不是每个链接都要维护双向
- 链接多了不等于知识网络成立了

参见 `docs/conventions/naming.md` 的六条命名规则。

## 结构层的边界

结构层**管什么**：目录归属、元数据规范、链接约定、命名合规。

结构层**不管什么**：正文内容质量、知识的深度加工、演化决策。那些属于演化层。

结构层的目标不是完美，而是足够稳定让知识演化层可以正常运作。一个不完美的结构也比频繁重构的结构好。
