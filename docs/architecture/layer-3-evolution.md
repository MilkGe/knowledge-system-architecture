# 演化层 (Layer 3: Evolution)

知识从"刚采集的原材料"到"稳定可复用的认知"的自然过程。

系统不强迫知识走固定协议，只提供状态标记和演化动作，让知识按实际使用自然成熟。

## 核心模型：养料消耗

Inbox 笔记是基础养料（消耗品），不是永久存储。加工后原始文件不保留。

| 输入类型 | 加工方式 | 产出 | 原始文件 |
|---------|---------|------|---------|
| 单篇外源内容（视频转录/文章） | refine + connect → seed | 一篇结构化笔记 | 删除 |
| 多篇同主题内容 | refine + distill → seed/developed | 一篇合并笔记 | 全部删除 |
| 个人半成品笔记 | connect + 归档定位 → seed/developed | 一篇归属到 PARA 的笔记 | 保留 |
| 外部链接/URL 集合 | 补采或废弃 | 按实际判断 | 无产出时删除 |

外源内容是消耗品。个人思考笔记本身就是半成品，不是消耗品。

### "有血有肉"的标准

加工后的笔记应该读起来像自己写的，不是来源索引：

- 结构服务于逻辑，不服务于形式
- 包含个人经验关联（"这个方案跟我之前做 X 的决策逻辑很像"）
- 指向自己的未解决问题（"Y 方案能否解决 Z？需要实测"）
- 不需要处处标注来源出处

## 状态

每篇笔记的 `status` 字段记录其演化阶段，5 个状态覆盖整个生命周期：

| 状态 | 含义 | 典型行为 |
|------|------|---------|
| **raw** | 原始采集，未加工 | 刚刚进入 Inbox，只有原文/转录 |
| **seed** | 已初步处理，有潜力 | 已添加元数据、已有初步要点提炼 |
| **developed** | 已系统化整理 | 已与体系建立关联、已有个人理解 |
| **stable** | 已形成稳定认知 | 已被多次引用或复用、内容经过实践验证 |
| **archived** | 已归档 | 知识已过时/已压缩/不再活跃参与关联 |

状态是单向推进还是可回溯，由人决定，不由系统规定。

## 演化动作

演化动作是一组可识别的操作标记，不是协议步骤。动作不强制顺序，不要求全部执行：

| 动作 | 含义 | 状态变化 | 执行者 |
|------|------|---------|--------|
| collect | 采集/收藏 | → raw | 自动 |
| refine | 提炼要点、修正转录、结构化正文 | raw → seed | AI 做初版，人审核 |
| connect | 建立关联：添加 wikilink、归属 PARA | seed → developed | AI 建议，人确认 |
| distill | 提炼为可复用认知：写总结、抽原则 | developed → stable | 人主导，AI 辅助 |
| apply | 在实际场景中使用并记录反馈 | → stable 或触发回流 | 人 |
| archive | 归档 | → archived | AI 或人 |

## 沉淀机制

系统不通过 AI 推导来"生成深度"。"深度"来自真实使用中的自然沉淀：

| 信号 | 含义 | 建议动作 |
|------|------|---------|
| 某笔记被引用 ≥ 3 次 | 它在体系中开始具备参考价值 | 可考虑从 seed 推向 developed |
| 某笔记被反复访问/编辑 | 它在持续使用 | 可考虑 distill |
| 某笔记长期（> 90 天）未被引用 | 它可能没有实际价值 | 可考虑 archive |
| 多篇笔记指向同一概念 | 该概念值得单独提炼 | 可选创建一篇专门的概念笔记 |

沉淀信号只是建议，不强制执行。

## 与结构层的关系

演化层不维护独立的对象体系。所有状态信息通过文件的 YAML `status` 字段表达。概念的聚类通过结构层的目录归属和 wikilink 来实现，不需要额外机制。
